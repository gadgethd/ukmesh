## Change and rationale

`scripts/ci-retry.py` gives recognized transient image and apt failures at most
three command attempts, sleeping 5s and then 10s. It streams output and returns
the last failing command's exit status on exhaustion. Successful commands are
never replayed merely because their logs contain a network warning.

The workflow preloads the pinned Go test image, all 13 external Compose images,
and the eight distinct Dockerfile base images. The Compose inventory excludes
every image built locally, including aliases reused by services without their
own `build` block; `pull --ignore-buildable` alone would incorrectly pull the
local health-check alias. No registry was added.

BuildKit can still fetch metadata after a pull, so each existing Docker build
command also uses the helper. Registry failures are classified from the final
causal error. Shell build failures are eligible only when the failing layer
starts with apt; npm/Go compilation, audits and test commands are not retried.
Successful image layers remain cached when an apt failure restarts a build.

All three apt image layers now use `APT::Update::Error-Mode=any`, making failed
index downloads fail rather than accepting stale indexes. The health-check apt
installation is a separate layer from its existing Git checkout and npm work.
Its non-network apt purge remains unchanged. Playwright dependency installation
uses the apt retry mode separately from browser installation and E2E execution.

The previously floating `python:3.12-slim` and `golang:1.23-bookworm` references
now have registry-verified multi-platform digest pins, following the repository's
existing convention without changing their requested language versions.

## Network inventory and failure policy

All three workflow files were read; the changes target the CI workflow's
`Workers and Compose` job. The separate mobile and signed-release workflows
retain their existing triggers and steps.

| Network operation in Workers and Compose | Policy |
| --- | --- |
| Checkout; Node and Python setup downloads | Existing pinned actions and their own behavior; no custom retry. |
| Operator script `npm ci` and `npm audit` | Existing npm behavior; audit/typecheck/test failures remain fatal. |
| Dockerfile `FROM`, Redis/Go/Mosquitto test images, Compose runtime images, monitoring tool images | Explicit bounded pulls; BuildKit metadata failures also covered by build retry. |
| Worker build: apt indexes/packages and PyPI requirements | Strict apt update plus bounded apt-layer retry; pip's existing behavior and hash enforcement unchanged. |
| HopReach parity and performance runs: Go toolchain/module downloads | Existing Go behavior; tests and performance gates run once and remain fatal. |
| Application builds: npm registry, health-check Git fetch, Go modules, apt mirrors | Custom retries cover registry acquisition and apt-only failing layers; other operations retain existing behavior. |
| Bootstrap and empty-volume smoke: already pulled images, broker/database traffic, local HTTP/WebSocket assertions | Existing assertions and failure behavior unchanged. |
| Playwright: npm registry, apt OS dependencies, Chromium download | Apt dependency command gets bounded retry; npm and browser download retain existing behavior. |
| E2E browser requests against the isolated stack | Existing tests and assertions; no custom retries or skips added. |
| Monitoring validation; final operator safety tests | Images preloaded; validation and mocked safety checks retain their original failure behavior. |

Recognized retry classes are HTTP 408/429/500/502/503/504 acquisition responses,
Docker rate-limit diagnostics, connection reset/timeout, TLS handshake timeout,
temporary DNS resolution failure, apt hash mismatch, and apt unexpected-size /
mirror-sync diagnostics. A nonzero command status is required.

Authentication/authorization errors, missing images/platform manifests, certificate
trust/expiry errors, apt signature/key failures, missing packages and unsatisfied
dependencies fail immediately. Unknown errors and missing BuildKit causal
summaries fail immediately. Application compile failures, security gates,
worker tests, benchmarks, smoke assertions and E2E assertions retain their
existing fatal behavior; none are wrapped in retries. The last failure after
three eligible attempts still fails the job. No `continue-on-error` was added.

## Deliberately excluded and open questions

- No deployment, service restart, live configuration, production database,
  migrations, registry mirror, build-cache infrastructure or new third-party
  retry action was changed. Images have unique local test tags.
- The helper is scoped to CI; signed-release build retry policy was not changed.
  The three shared Dockerfiles do inherit strict apt index failure handling.
- Transient Git/npm/PyPI/Go-module/browser-download errors retain their clients'
  existing behavior. Unknown failure formats intentionally fail immediately;
  extend the classifier only from observed evidence.
- Three attempts cannot hide a sustained outage. If observed outages exceed this
  window, propose reuse of the existing GHA BuildKit cache or an operator-owned
  registry cache to Ben; neither is implemented here.
- TokenSave returned no relevant symbols and there is no worktree-local SQLite
  index, so workflow/Dockerfile analysis used the actual files.
